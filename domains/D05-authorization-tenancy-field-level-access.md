## Decision tree

Machine readable at `trees/D05.json`. This is the rendered view.

- **Does the application authorise on objects (BOLA) or on functions (BFLA) or both?**
  - _why:_ The test procedure diverges completely. BOLA needs two identities and object ids. BFLA needs a role matrix.
- `Both, typical`
  - **Do you have two accounts at different privilege levels and at least one object owned by a third?**
  - `Yes`
    - action: run the same request set as both identities, diff responses, then substitute ids across owners
    - tools: `d05-newman`, `d05-autorize`, `d05-mitmproxy`
    - oracle: `differential across identities`
    - **Does the difference survive a third identity and a negative control?**
  - `No`
    - action: create them. authz cannot be tested with one identity, and this is the most common reason it is not tested
- `Authorisation is in the database (RLS, policies)`
  - action: test the client SDK path directly, not the HTTP API. look for policies that reference a user supplied claim
  - tools: `d05-supabase-rls`
  - oracle: `row visible that policy should hide`
- `Authorisation is in a gateway or policy engine`
  - action: test the gateway and the service independently. the gap between them is the finding surface
  - oracle: `same request, different decision at two layers`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| BOLA write | write to an object not in the session scope | object level check on every item | ownership mismatch per write |
| BFLA | role to endpoint matrix anomaly | function level authz, deny by default | 403 to 200 transition per role |
| mass assignment | write to a field absent from the role's request schema | explicit allowlist binding | unexpected field in write payload |
| tenant escape | cross tenant reference | tenant from token, never body | cross tenant reference audit |
| bulk authz skip | heterogeneous ownership in one batch | authorise each element | batch ownership mix |
| stale authz | decision timestamp older than revocation | authorise against authoritative store | revocation to decision lag |
| RLS bypass | query returning rows outside policy | policy tested against the client SDK path | policy coverage per table |
