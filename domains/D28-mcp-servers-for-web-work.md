## Decision tree

Machine readable at `trees/D28.json`. This is the rendered view.

- **Are you wiring a server, or reviewing one?**
  - _why:_ Wiring is an install problem. Reviewing is a supply chain problem, and the second is the one nobody does.
- `Wiring`
  - action: use a config that is known to start. never add a server by name and link alone
  - tools: `d28-rea`, `d28-mcps`
  - oracle: `server starts and lists tools`
- `Reviewing`
  - action: read every tool description as if it were a prompt, because it is. then scan for injection and pin the hashes
  - tools: `d28-mcp-scan`, `d28-spec`
  - oracle: `description hash manifest`
- `Choosing from a registry`
  - action: registry size is a supply chain risk, not a feature. pick the smallest server that does the job
  - tools: `d28-awesome-mcp`
  - oracle: `server passes the scan and the pin check`
- `Testing an agent that uses servers`
  - action: inject through tool output and measure both attack success and utility loss
  - tools: `d28-agentdojo`, `d28-promptfoo`
  - oracle: `attack success plus utility delta`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| tool poisoning | description hash change | pin and review descriptions as code | description manifest diff |
| credential theft via server | server requesting scopes beyond its stated purpose | least privilege tokens per server | scope request anomaly |
| registry supply chain | new or changed server in config | allowlist, pin versions | config change |
| tool output injection | instructions in tool output followed by a call | label tool output as data | instruction pattern in output |
