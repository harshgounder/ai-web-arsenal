## Decision tree

Machine readable at `trees/D18.json`. This is the rendered view.

- **What is the trust decision: a package, an action, or a build?**
  - _why:_ Three different supply chains with three different checks. Most reviews only cover packages and call it done.
- `A package`
  - action: check registry priority and namespace scope, then whether a private name could resolve publicly
  - tools: `d18-trivy`, `d18-grype`
  - oracle: `a package resolved from the wrong registry`
- `A CI action or plugin`
  - action: an action is code executed with your token. read what it does and check whether the tag is mutable
  - tools: `d18-scorecard`
  - oracle: `mutable tag or unreviewed action executing`
- `A build`
  - action: provenance and signing. an unsigned artefact is a claim, not a fact
  - tools: `d18-slsa`, `d18-cosign`
  - oracle: `signature verified against the expected identity`
- `A secret leak`
  - action: scan the repo and the bundle, then verify the secret is live
  - tools: `d18-gitleaks`
  - oracle: `secret verified against its service`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| dependency confusion | a private name resolved from the public registry | scoped registry, priority rules | registry source mismatch |
| typosquat | a name one character from a popular package | allowlist, review new dependencies | new dependency added |
| malicious CI action | action tag changed or unpinned | pin to digest, review actions | action reference change |
| unsigned artefact | no signature or unexpected identity | enforce signing and verify identity | signature absent |
| public SBOM disclosure | build metadata published | strip version detail from public artefacts | version string in public asset |
