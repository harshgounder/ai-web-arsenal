### Details that matter

**jwt_tool**  
- preconditions: `a JWT you can decode`, `the verifier accepts a header you can influence`
- oracle: `token accepted after tampering`, `claim change reflected server side`
- defense levels it addresses: F2
- detected by: alg or kid mismatch at the verifier
- note: Runs all tests with -M at, then a specific tamper with -T. Start there, not with a hand written payload.

**hydra**  
- preconditions: `a login endpoint`, `no lockout, or a lockout policy you have tested`
- oracle: `valid credential in the output`
- defense levels it addresses: F2
- detected by: failed login distribution per IP and per account
- note: The lockout test matters more than the cracking. Run one account first and watch for lockout before any list.

**medusa**  
- preconditions: `login endpoint`, `no per IP throttle`
- oracle: `valid credential found`
- defense levels it addresses: F2
- detected by: failed login distribution per IP and per account
- note: Parallelism is both the feature and the reason to be careful: it is the fastest way to lock out every account at once.

**ffuf**  
- preconditions: `an auth endpoint that behaves differently for known and unknown accounts`
- oracle: `status, length or timing cluster separating existent from non existent`
- defense levels it addresses: F2
- detected by: response or timing difference for unknown accounts

**JWT Editor (Burp extension)**  
- oracle: `modified token accepted by the server`, `claim change reflected in the session`
- defense levels it addresses: F2
- detected by: alg or kid mismatch at the verifier
- note: BApp store deep links change. Link goes to the store; search for JWT Editor.

**SAML Raider (Burp extension)**  
- preconditions: `SAML SSO in front of the app`, `a captured assertion`
- oracle: `assertion accepted after modification`
- defense levels it addresses: F2
- detected by: signature not verified over the signed element
- note: BApp store URL changes; resolve the current listing from the store rather than trusting a fixed path.

**Keycloak (as a test IdP)**  
- oracle: `behaviour differs from the specification`, `redirect accepted to an unregistered URI`
- defense levels it addresses: F2
- detected by: redirect URI not exact matched
- note: Most OAuth findings are configuration findings. A local IdP lets you confirm the class before touching a target.

## Decision tree

Machine readable at `trees/D04.json`. This is the rendered view.

- **Is authentication local, federated, or both?**
  - _why:_ The attack set is almost disjoint. Local auth is about policy and enumeration. Federation is about assertion and redirect handling.
- `Local`
  - **Is there any lockout or rate limit on the login endpoint?**
  - `No`
    - action: test one account first to confirm, then enumerate and test credentials at a controlled rate
    - tools: `d04-hydra`, `d04-ffuf`
    - oracle: `valid credential or a distinguishable account-exists response`
  - `Yes`
    - action: treat lockout as the target: is it per account, per IP or global, and can it deny service to a victim
    - tools: `d04-medusa`
    - oracle: `lockout triggered for a victim without an attempt from you`
- `Federated (OAuth, OIDC, SAML)`
  - **Can you see the assertion or token?**
  - `Yes`
    - action: test signature handling, algorithm, audience and replay before anything else
    - tools: `d04-burp-jwt`, `d04-jwt_tool`, `d04-saml-raider`
    - oracle: `modified assertion accepted`
  - `No`
    - action: test redirect URI handling, scope, state and nonce first. those are configuration classes and need no token
    - tools: `d04-keycloak`, `d04-rfc9700`
    - oracle: `code or token delivered to a URI you control`
- `Passkeys or WebAuthn present`
  - action: test registration and assertion separately. attestation, origin and user verification are three different checks
  - tools: `d04-webauthn`
  - oracle: `assertion accepted for the wrong origin or user`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| credential stuffing | failed login distribution per IP and per account | rate limit per account, not per IP | failed auth burst |
| account enumeration | response or timing difference for unknown accounts | uniform responses and timing | registration or reset probe rate |
| JWT tampering | alg or kid mismatch at the verifier | fixed algorithm, no negotiation from the token | jwt validation failure |
| SAML signature bypass | signature not verified over the signed element | validate signature over the canonical element, reject unsigned | assertion parse anomaly |
| OAuth redirect abuse | redirect URI not exact matched | exact registered URI, PKCE | redirect mismatch |
| MFA fatigue | repeated push approves for one account | number matching, rate limit, phishing resistant factors | push volume per account |
| session fixation | session id unchanged after authentication | rotate the session on privilege change | session id continuity across login |
