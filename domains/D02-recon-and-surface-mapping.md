### Details that matter

**subfinder**  
- preconditions: `a root domain and passive sources`
- oracle: `hostnames not visible in any other source`
- defense levels it addresses: F1
- note: Passive first. It costs the target nothing and often finds the forgotten subdomain.

**dnsx**  
- preconditions: `a hostname list`
- oracle: `resolved hosts, cname chains and dangling records`
- defense levels it addresses: F1
- note: The -cname plus -a pair is how you find subdomain takeover candidates mechanically.

**httpx**  
- preconditions: `a host list`
- oracle: `live hosts with status, title and detected technology`
- defense levels it addresses: F1
- note: This is the pivot from names to a surface. Everything downstream consumes its json.

**naabu**  
- preconditions: `a host list`
- oracle: `open ports per host`
- defense levels it addresses: F1
- note: Only after httpx. Most web work needs 80/443 and the few adjacent ports, not a full sweep.

**whatweb**  
- preconditions: `a live host`
- oracle: `frameworks, servers, versions and plugins`
- defense levels it addresses: F1
- note: Aggression 1 only. Higher aggression is loud and rarely worth it.

**nmap**  
- preconditions: `a host and port`
- oracle: `service banner and version`
- defense levels it addresses: F1
- note: The fallback arbiter. If httpx and the HTML disagree about the stack, nmap settles it.

**katana**  
- preconditions: `a live host`
- oracle: `endpoint list including routes only JS reveals`
- defense levels it addresses: F1
- note: The -jc flag is the point. A crawler that does not parse JS misses the whole modern surface.

**gau**  
- preconditions: `a domain`
- oracle: `historical endpoint list`
- defense levels it addresses: F1
- note: Free history. Run it before touching the host: it often lists endpoints that were removed from the app but not from the server.

**ffuf**  
- preconditions: `a wordlist and a live host`
- oracle: `status and size clusters revealing hidden paths`
- defense levels it addresses: F1
- note: Set -rate. An agent that ignores rate is a denial of service.

**feroxbuster**  
- preconditions: `a live host`
- oracle: `nested directories and files`
- defense levels it addresses: F1
- note: Recursion finds the nested app that the flat wordlist misses.

**gobuster**  
- preconditions: `a wordlist`
- oracle: `vhosts or paths that respond differently`
- defense levels it addresses: F1
- note: vhost mode is the underused one: shared IP, different app per Host header.

**arjun**  
- preconditions: `an endpoint`
- oracle: `hidden parameters`
- defense levels it addresses: F1
- note: Hidden parameters are where mass assignment and logic bugs start.

## Decision tree

Machine readable at `trees/D02.json`. This is the rendered view.

- **Is your goal coverage of an estate, or depth on one app?**
  - _why:_ The two goals produce opposite recon strategies and most people run the depth strategy while claiming coverage.
- `Coverage of an estate`
  - action: passive first, then probe, then fingerprint. never crawl every host, fingerprint and rank instead
  - tools: `d02-subfinder`, `d02-dnsx`, `d02-httpx`, `d02-whatweb`
  - oracle: `host inventory with technology per host`
- `Depth on one app`
  - **Do you have a capture of a real session yet?**
  - `No`
    - action: browse once through the proxy. a capture beats a crawl because it includes authenticated routes
    - tools: `d02-rea-capture`
    - oracle: `endpoint inventory with auth requirement`
  - `Yes`
    - action: diff three sources: crawl, bundle routes, capture. the set difference is the finding surface
    - tools: `d02-katana`, `d02-rea-bundle`, `d02-rea-capture`
    - oracle: `route present in one source and absent in the others`
- `Find forgotten assets`
  - action: historical urls plus certificate transparency plus dns history, then confirm liveness
  - tools: `d02-gau`, `d02-dnsx`, `d02-httpx`
  - oracle: `live endpoint absent from current navigation`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| subdomain takeover | dangling cname to an unclaimed service | inventory cnames, claim or remove | cname to unowned service |
| shadow API discovery | route present in bundle but never called | inventory from code, not only from traffic | route in bundle absent in logs |
| vhost confusion | different app served per Host header on one IP | default vhost denies unknown hosts | host header variance |
| exposed non production host | staging or dev host with weaker auth | same auth posture everywhere, or no public DNS | non prod host reachable |
| parameter hiding | parameters accepted but undocumented | explicit allowlist per endpoint | unexpected parameter accepted |
