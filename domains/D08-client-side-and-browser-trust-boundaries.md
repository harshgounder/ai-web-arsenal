## Decision tree

Machine readable at `trees/D08.json`. This is the rendered view.

- **Does the value reach a DOM sink?**
  - _why:_ Client side is entirely about sinks. If nothing reaches a sink, there is no class here, no matter how many sanitizer weaknesses you find.
- `Unknown`
  - action: read the listeners and the bundle. do not guess at innerHTML
  - tools: `d08-rea-listeners`, `d08-rea-scenario`
  - oracle: `a sink identified in recovered source`
- `Yes, and CSP exists`
  - action: score the CSP first. a weak policy changes which payloads are worth trying
  - tools: `d08-csp-eval`
  - oracle: `bypass class named by the evaluator`
- `Yes, no CSP`
  - action: pick a context appropriate payload, confirm execution with a callback under a control
  - tools: `d08-dalfox`, `d08-payloads`
  - oracle: `execution confirmed, control does not execute`
- `Sanitiser in path`
  - action: test the sanitiser version and the parser differential. the bypass lives between the two parsers
  - tools: `d08-dompurify`
  - oracle: `output that survives sanitisation and executes`
- `Trusted Types enforced`
  - action: the class is largely closed. report it as a positive and look at the server side instead
  - tools: `d08-trusted-types`
  - oracle: `n/a`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| DOM XSS | CSP violation report, sink reachability scan | Trusted Types, safe sinks, CSP with nonces | csp-report and unsafe sink in source |
| CSP bypass | policy allows an unsafe source | nonce or hash based policy, no unsafe-inline | csp-evaluator weakness |
| postMessage abuse | message handler without origin check | check origin and shape on every handler | message without origin validation |
| prototype pollution | merge into prototype from parsed input | null prototype objects, schema validation | prototype key in payload |
| client side template injection | template expression evaluated in the browser | no client side template from user input | expression in rendered output |
