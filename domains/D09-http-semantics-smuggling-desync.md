### Details that matter

**smuggler**  
- preconditions: `two layers that disagree about message framing`
- oracle: `a request that desyncs the backend`, `a second response arriving on the wrong connection`
- note: Only against infrastructure you own or a lab. A desync can corrupt other users' requests, which makes it the most dangerous class here.

**h2cSmuggler**  
- preconditions: `a front end that forwards an upgrade header`, `a backend that speaks h2c`
- oracle: `an internal request reaching a path the front end would block`
- detected by: upgrade header forwarded to a backend that speaks h2c

**mitmproxy**  
- preconditions: `a client you can proxy`
- oracle: `the exact bytes on the wire`

**curl**  
- preconditions: `a shell`
- oracle: `differential response when framing is changed`

**PortSwigger HTTP/2 research**  
- detected by: header injection through pseudo header conversion
- note: HTTP/2 smuggling separated this domain into two eras. Anything that only tests HTTP/1.1 is testing half the surface.

**RFC 9112 (HTTP/1.1)**  
- note: Read the message body length section. Every smuggling variant is a disagreement about that section.

**nuclei**  
- preconditions: `a host and templates`
- oracle: `template match with evidence`

## Decision tree

Machine readable at `trees/D09.json`. This is the rendered view.

- **Are you in a lab or on shared infrastructure?**
  - _why:_ This question comes first, before any technique. A desync can corrupt other users' in flight requests. On shared infrastructure that is not a test, it is an incident.
- `On shared infrastructure`
  - action: stop. document the suspicion and the reason, then move to a lab. nothing else in this tree applies
  - oracle: `n/a`
- `In a lab`
  - **What sits in front of the back end?**
  - `Unknown`
    - action: fingerprint the chain first. version, keep alive behaviour, connection reuse
    - tools: `d09-nuclei`, `d09-curl`
    - oracle: `proxy behaviour identified`
  - `HTTP/1.1 proxy`
    - action: test CL.TE and TE.CL with paired requests and a timing oracle, then obfuscation variants
    - tools: `d09-smuggler`
    - oracle: `a response that belongs to another request`
  - `HTTP/2 front end`
    - action: test downgrade and h2c upgrade paths. this is the half most tools miss
    - tools: `d09-h2c`
    - oracle: `an internal request reaching a blocked path`
- `Want to learn the class`
  - action: read the framing rules, then do the labs. do not start with a tool
  - tools: `d09-rfc9112`, `d09-portswigger`
  - oracle: `lab solved with a hand crafted request`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| CL.TE smuggling | front end and back end disagree on framing | same parser, reject ambiguous requests | conflicting content-length and transfer-encoding |
| TE.CL | chunked handling mismatch | normalise at the edge, one parser | malformed chunk size |
| h2c upgrade smuggling | upgrade header forwarded to a backend that speaks h2c | strip upgrade, disable h2c internally | upgrade header to an internal hop |
| HTTP/2 downgrade | header injection through pseudo header conversion | strict RFC 9113 conversion | pseudo header in a downgraded request |
