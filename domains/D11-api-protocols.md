## Decision tree

Machine readable at `trees/D11.json`. This is the rendered view.

- **Do you have a schema or a capture for this API?**
  - _why:_ Everything downstream depends on this. Guessing without a schema is the least efficient mode and the most common mistake.
- `Yes, OpenAPI or GraphQL schema in hand`
  - **Is the schema generated by the vendor or recovered by you?**
  - `vendor generated`
    - **Does the live API match the spec on undocumented fields?**
  - `recovered from traffic`
    - **Are there endpoints in the client that traffic never touched?**
- `No schema, only a live endpoint`
  - **What protocol?**
  - `GraphQL`
    - action: fingerprint engine, try introspection, if off recover fields by suggestion abuse
    - tools: `graphw00f`, `graphql-cop`, `clairvoyance`, `inql`
    - oracle: `schema_partial_recovery`
  - `gRPC`
    - action: attempt reflection, then describe, then call with empty message to map fields
    - tools: `grpcurl`
    - oracle: `reflection_listing`
  - `REST`
    - action: capture one authenticated session, convert to spec, then fuzz from the spec
    - tools: `mitmproxy`, `mitmproxy2swagger`, `kiterunner`, `ffuf`
    - oracle: `spec_parses`
  - `WebSocket or SSE`
    - action: record frames, look for client side trust and message type confusion
    - tools: `rea inspect_web_network_capture`
    - oracle: `frame_schema_divergence`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| BOLA | object id enumeration pattern per session | object level authorisation check on every read, not on the list endpoint | authz-failure rate per user |
| BFLA | role to endpoint matrix anomaly | function level authorisation, deny by default | 403 to 200 transition per role |
| GraphQL introspection abuse | introspection query signature and field suggestion probing | disable suggestions too, not just introspection | query depth and suggestion error rate |
| GraphQL batching rate bypass | operations per request ratio | cost analysis per operation, not per request | batch size threshold |
| mass assignment | extra fields accepted on write | explicit allowlist binding, never object hydration from body | unexpected field in write payload |
| spec drift | live response shape differs from spec | contract testing in CI | schema conformance check |
| gRPC reflection exposed | reflection service calls | disable reflection in production | grpc.reflection access |
| token confusion across services | same token accepted by services with different audiences | audience validation per service | audience mismatch log |
