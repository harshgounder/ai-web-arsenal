### Details that matter

**kiterunner**  
- preconditions: `API routes are guessable from naming conventions`, `no global 404 normalisation`
- oracle: `differential_response`, `status_code_divergence`
- defense levels it addresses: F2
- detected by: 404 volume anomaly, WAF path enumeration rule
- runnable: capture one authenticated request from the API -> kr scan <host> -w routes.kite -x 8, wait for 429 before raising -> diff the discovered routes against the captured set, the delta is the target
- note: The route wordlists matter more than the tool. Assetnote's kite files encode real API shapes.

**ffuf**  
- preconditions: `a fuzz position exists in the request`
- oracle: `differential_response`, `size_or_status_cluster`
- defense levels it addresses: F2, F3
- detected by: request rate anomaly, CRS 913100 scanner user agent
- runnable: pick one fuzz position and one signal, status or size -> ffuf -w list -u URL -of json -rate 30 -> re-run the top hits with a control value that should 404
- note: Set -rate. An agent that ignores rate is a denial of service, not a tester.

**arjun**  
- preconditions: `the server accepts parameters it does not advertise`
- oracle: `response_delta_per_parameter`, `reflection_detection`
- defense levels it addresses: F2
- detected by: parameter count anomaly
- runnable: arjun -u endpoint -oJ params.json -> for each new parameter, send it with a benign value and with an absurd one -> the parameter that changes behaviour is the hypothesis

**clairvoyance**  
- preconditions: `introspection disabled but field suggestions enabled`, `or error messages leak field names`
- oracle: `schema_partial_recovery`, `suggestion_error_differential`
- defense levels it addresses: F3
- detected by: introspection query signature and field suggestion probing
- runnable: confirm introspection is actually off with a direct query -> clairvoyance -o schema.json -w wordlist URL/graphql -> compare recovered fields to what the UI calls, the gap is unauthorised surface
- note: This is the canonical example of a tool that exists because a defence (introspection off) was assumed sufficient and was not.

**InQL**  
- preconditions: `introspection enabled, or schema otherwise obtained`
- oracle: `query_success`, `data_exposure_differential`
- defense levels it addresses: F2
- detected by: introspection query signature
- runnable: inql -t URL/graphql -o out -> pick the mutation with the most privileged sounding name -> send it with a minimal body and read the error, the error describes the input shape

**graphw00f**  
- preconditions: `an exposed graphql endpoint`
- oracle: `engine_identification`
- defense levels it addresses: F1
- detected by: operations per request ratio
- runnable: graphw00f -d -t URL/graphql -> note engine and version -> look up that engine's introspection and batching quirks before payload selection
- note: Engine matters because batching, alias limits and introspection quirks differ per engine. Fingerprint before you payload.

**mitmproxy2swagger**  
- preconditions: `you captured real traffic from a real client`
- oracle: `spec_parses`, `spec_matches_observed_responses`
- defense levels it addresses: F1
- detected by: not detectable, this is offline
- runnable: mitmdump -w flows while using the product normally -> mitmproxy2swagger -i flows -o spec.yml -p https://api -> open spec.yml, every path marked ignored is a question: why did it not match
- note: The single highest leverage API step. A spec turns guessing into property testing.

**grpcurl**  
- preconditions: `server reflection enabled, common in internal services exposed by mistake`
- oracle: `rpc_response`, `reflection_service_listing`
- defense levels it addresses: F2
- detected by: reflection service calls
- runnable: grpcurl -plaintext host:443 list -> if reflection answers, describe every service -> call the least privileged looking method with an empty message and read the field error
- note: Reflection on is equivalent to a free full schema. Nobody checks it.

**schemathesis**  
- preconditions: `a schema exists, real or recovered`
- oracle: `crash`, `status_code_violation`, `schema_response_mismatch`
- defense levels it addresses: F3
- detected by: introspection query signature and field suggestion probing
- runnable: obtain or recover a spec -> schemathesis run spec.yml --checks all --hypothesis-seed 0 -> for each failure, replay with the recorded seed, that is the evidence
- note: Reproducible failures with hypothesis seeds, which makes it usable as evidence.

**RESTler**  
- preconditions: `multi step API with producer and consumer endpoints`, `OpenAPI spec available`
- oracle: `sequence_crash`, `state_invariant_violation`
- defense levels it addresses: F3
- detected by: abnormal call sequence graph
- runnable: restler compile --api_spec spec.json, this generates the grammar -> restler test --grammar_file g.json, then restler fuzz -> inspect sequence bugs, they need more than one call to reproduce
- note: The only credible stateful API fuzzer. Heavy build, worth it for logic bugs.

**graphql-cop**  
- preconditions: `graphql endpoint reachable`
- oracle: `misconfiguration_confirmed_by_response`
- defense levels it addresses: F2
- detected by: introspection query signature and field suggestion probing
- runnable: graphql-cop -t URL/graphql -> take each finding and confirm it by hand, the tool over-reports -> record the response, not the tool verdict

**Damn Vulnerable GraphQL Application**

**BatchQL**

## Decision tree

Machine readable at `trees/D11.json`. This is the rendered view.

- **Do you have a schema or a capture for this API?**
  - _why:_ Everything downstream depends on this. Guessing without a schema is the least efficient mode and the most common mistake.
- `Yes, OpenAPI or GraphQL schema in hand`
  - **Is the schema generated by the vendor or recovered by you?**
  - `vendor generated`
    - **Does the live API match the spec on undocumented fields?**
  - `recovered from traffic`
    - **Are there endpoints in the client that traffic never touched?**
- `No schema, only a live endpoint`
  - **What protocol?**
  - `GraphQL`
    - action: fingerprint engine, try introspection, if off recover fields by suggestion abuse
    - tools: `graphw00f`, `graphql-cop`, `clairvoyance`, `inql`
    - oracle: `schema_partial_recovery`
  - `gRPC`
    - action: attempt reflection, then describe, then call with empty message to map fields
    - tools: `grpcurl`
    - oracle: `reflection_listing`
  - `REST`
    - action: capture one authenticated session, convert to spec, then fuzz from the spec
    - tools: `mitmproxy`, `mitmproxy2swagger`, `kiterunner`, `ffuf`
    - oracle: `spec_parses`
  - `WebSocket or SSE`
    - action: record frames, look for client side trust and message type confusion
    - tools: `rea inspect_web_network_capture`
    - oracle: `frame_schema_divergence`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| BOLA | object id enumeration pattern per session | object level authorisation check on every read, not on the list endpoint | authz-failure rate per user |
| BFLA | role to endpoint matrix anomaly | function level authorisation, deny by default | 403 to 200 transition per role |
| GraphQL introspection abuse | introspection query signature and field suggestion probing | disable suggestions too, not just introspection | query depth and suggestion error rate |
| GraphQL batching rate bypass | operations per request ratio | cost analysis per operation, not per request | batch size threshold |
| mass assignment | extra fields accepted on write | explicit allowlist binding, never object hydration from body | unexpected field in write payload |
| spec drift | live response shape differs from spec | contract testing in CI | schema conformance check |
| gRPC reflection exposed | reflection service calls | disable reflection in production | grpc.reflection access |
| token confusion across services | same token accepted by services with different audiences | audience validation per service | audience mismatch log |

## Gaps

Recorded, not hidden. `no-tool` means nothing usable exists. `coverage` means a required cell is empty.

| gap | class | build candidate |
|---|---|---|
| No tool recovers a GraphQL schema when both introspection and suggestions are off | no-tool | differential error oracle that recovers field names from validation messages, then type names from union errors |
| No tool diffs a client bundle's endpoint set against captured traffic automatically | no-tool | join rea analyze_web_bundle routes with rea inspect_web_network_capture urls, emit the set difference |
| No tool tests object level authorisation across N users automatically | no-tool | create M identities, replay every captured object request as each identity, flag any 200 that should be 403 |
| No credible WebSocket semantic fuzzer | no-tool | frame schema inference from capture plus type confusion mutations |
| No tool verifies a fix without a full rescan | no-tool | store the exact request that proved the finding, replay it as the retest, diff the oracle |
| L10 impact framing and L11 retest cells are empty in this domain | coverage | impact template per API class plus a retest harness |
| No WebSocket or server-sent event testing in this domain | no-tool | hand crafted frames with a raw socket client, plus an SSE client that forges Last-Event-ID and compares resumption across hops |
