## Decision tree

Machine readable at `trees/D07.json`. This is the rendered view.

- **Do you know which interpreter receives the value?**
  - _why:_ Every injection class is defined by its sink, and the payload is a consequence of the sink. Choosing a payload before a sink is how scanners produce false positives.
- `No, sink unknown`
  - action: find the sink first. arithmetic or syntax that only one interpreter evaluates beats a payload list
  - tools: `d07-rea-listeners`, `d07-sstimap`
  - oracle: `a response only that interpreter could produce`
- `Yes, a renderer`
  - action: read the handlers, pick a context payload, confirm with a callback under a control
  - tools: `d07-dalfox`, `d07-rea-listeners`
  - oracle: `execution confirmed by callback`
- `Yes, a query`
  - action: boolean and time based pairs, never a destructive statement
  - tools: `d07-sqlmap`, `d07-nosqlmap`
  - oracle: `differential or timing with a matched control`
- `Yes, a shell`
  - action: blind time based first, then a reversible side effect
  - tools: `d07-commix`
  - oracle: `timing control plus a benign artefact`
- `Yes, a deserializer`
  - action: identify the sink and the classpath, then match a gadget
  - tools: `d07-ysoserial`, `d07-ysoserial-net`
  - oracle: `callback from the target process`
- `Second order suspected`
  - action: store then trigger a different read. the oracle is in the second request
  - tools: `d07-webgoat`
  - oracle: `effect appears on a later read`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| SQL injection | query error signatures, unusual query time | parameterised queries everywhere | error and time based pairs |
| XSS | payload reflected unencoded | context aware output encoding plus CSP | reflected markup in a response |
| command injection | process spawn from a request handler | no shell, argv only | shell spawn in request context |
| SSTI | arithmetic evaluation in output | logic-less templates, no user template source | expression evaluation attempt |
| deserialization | unexpected class in a deserialised stream | allowlisted types, signed blobs | deserialisation type anomaly |
| NoSQL operator injection | operator syntax in a JSON body | type checking, no object pass through | operator key in body |
| second order injection | stored value re-entering a sink | encode at the sink not the source | sink receives previously stored data |
