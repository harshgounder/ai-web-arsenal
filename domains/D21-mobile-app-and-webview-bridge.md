## Decision tree

Machine readable at `trees/D21.json`. This is the rendered view.

- **Do you have the package, or only a running app?**
  - _why:_ Static gives you structure and a stable target. Runtime gives you values. Most people skip static and then fight pinning for an hour.
- `Have the package`
  - action: decode, list exported components, extract strings, then find the API host and auth scheme
  - tools: `d21-rea-android`, `d21-rea-android-res`, `d21-apktool`, `d21-jadx`
  - oracle: `endpoints and keys recovered from the package`
- `Only a running app`
  - action: proxy it first. if pinned, hook the pinning check and retry
  - tools: `d21-frida`, `d21-objection`
  - oracle: `requests visible through the proxy after the bypass`
- `A webview in the app`
  - **What can the loaded page call?**
  - `A bridge object`
    - action: enumerate the exposed methods, then test what they do with attacker controlled arguments and from an attacker controlled origin
    - tools: `d21-rea-android-class`
    - oracle: `bridge method executed from an origin it should not accept`
  - `Deep links only`
    - action: test intent or URL handling for parameter injection and for reaching privileged screens
    - tools: `d21-rea-android`
    - oracle: `privileged screen reached without auth`
- `Flutter or mini program`
  - action: the logic is not in DEX. use the AOT or package specific tool first, or you will read nothing
  - tools: `d21-blutter`, `d21-wxapkg`
  - oracle: `recovered symbols or source`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| webview bridge abuse | bridge call from an unexpected origin | allowlist origins and methods, validate arguments | bridge call origin mismatch |
| certificate pinning bypass | instrumentation present, hooking framework loaded | pinning plus integrity checks, but assume bypass | frida or hook framework detected on device |
| exported component abuse | external intent reaching a privileged activity | exported false, permission on the component | intent to a non exported component |
| insecure deep link | deeplink with parameters reaching a privileged screen | validate and authorise on the parameter, not the route | deeplink with unexpected parameters |
| secret in the package | key material in resources or strings | no secrets client side, rotate what leaked | secret pattern in an APK |
