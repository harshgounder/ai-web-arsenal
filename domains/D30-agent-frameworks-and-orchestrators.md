## Decision tree

Machine readable at `trees/D30.json`. This is the rendered view.

- **Do you need one agent or several?**
  - _why:_ Most campaigns need one executor and one critic. Adding agents multiplies requests and detection, not findings.
- `One target, one stack`
  - action: Operator, Executor, Critic. stop there
  - tools: `d30-crewai`, `d30-openai-agents`
  - oracle: `critic verdict per finding`
- `Wide surface, many hosts`
  - action: add a read only recon fleet, keep judgement sequential
  - tools: `d30-langgraph`
  - oracle: `host inventory with per host confidence`
- `Long campaign`
  - action: add a bookkeeper that owns state and evidence paths, because context does not fit
  - tools: `d30-pentagi`
  - oracle: `resumable state file`
- `Comparing frameworks`
  - action: evaluate on handoff and guardrail primitives, not on agent count
  - tools: `d30-autogen`, `d30-cai`
  - oracle: `a critic loop implemented in under an hour`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| agent action outside plan | tool call not in the planned phase | per phase allowlist and budget | unplanned tool invocation |
| confirmation bias loop | finding rate high, survival rate low | separate critic with fresh context | critic reject rate |
| context collapse | later agents repeat earlier work | external state file, not context | duplicate work detection |
| scope drift | requests to hosts outside the allowlist | enforce at the request layer | out of scope host |
