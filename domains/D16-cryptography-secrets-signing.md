**CyberChef**  
- preconditions: `a blob of unknown encoded data`
- oracle: `a readable result and the recipe that produced it`
- note: Recipe export is the useful part: it makes the decode reproducible instead of a screenshot.

**PadBuster**  
- preconditions: `a CBC mode ciphertext`, `an oracle that distinguishes padding errors`
- oracle: `decrypted plaintext or a forged ciphertext`

**gitleaks**

**trufflehog**

**rea analyze_web_bundle**

- note: Request signing lives in client code by definition. If the app signs, the algorithm is in the bundle.

## Decision tree

Machine readable at `trees/D16.json`. This is the rendered view.

- **Is the weakness in a token, a secret, or a cipher?**
  - _why:_ Three different disciplines that share a domain name. Token attacks are about validation. Secret attacks are about exposure. Cipher attacks are about mathematics and oracles.
- `A token`
  - action: decode, then test validation: none, algorithm confusion, key confusion, claims. acceptance is the only oracle
  - tools: `d16-jwt-tool`, `d16-jwtio`
  - oracle: `server accepts a token it should reject`
- `A secret`
  - action: scan with verification on. an unverified candidate list is noise
  - tools: `d16-trufflehog`, `d16-gitleaks`
  - oracle: `secret verified live against its service`
- `A cipher`
  - action: find the oracle first. without a distinguishable error there is no attack
  - tools: `d16-padbuster`
  - oracle: `padding oracle distinguishes the two error classes`
- `A signed request`
  - action: the algorithm is in the client. recover it, then decide whether the key is client side
  - tools: `d16-rea-signing`
  - oracle: `a replayed signature accepted with a modified body`
- `A hash`
  - action: identify the type, then choose a wordlist and rule set. never guess the type
  - tools: `d16-hashcat`, `d16-john`
  - oracle: `plaintext or a measurable rate`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| algorithm confusion | alg in the token does not match the configured algorithm | pin the algorithm server side | alg mismatch |
| weak hashing | fast hash used for passwords | memory hard KDF | hash type at rest |
| secret in client artefact | key material in a bundle or APK | no secrets client side, rotate on discovery | secret pattern in a served asset |
| padding oracle | distinguishable decrypt error classes | uniform errors, authenticated encryption | decrypt error differential |
| nonce reuse | repeated IV or nonce per key | random or counter nonce with uniqueness proof | nonce collision |
