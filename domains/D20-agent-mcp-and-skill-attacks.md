## Decision tree

Machine readable at `trees/D20.json`. This is the rendered view.

- **What can the agent call?**
  - _why:_ The attack surface is the tool registry. Everything else is an input channel into it.
- `MCP servers`
  - **Are tool descriptions pinned or fetched fresh?**
  - `Fetched fresh`
    - action: the description is attacker influenceable if any server is compromised or added. scan for injection in descriptions and diff against a known good
    - tools: `d20-mcp-scan`
    - oracle: `description containing instructions`
  - `Pinned`
    - action: test the pinning itself: can a server change its description and be accepted
    - tools: `d20-mcp-scan`
    - oracle: `changed description accepted`
- `Skills or plugins`
  - action: treat skill files as code. review what they instruct the agent to do, and whether they can read secrets or call tools
  - tools: `d20-promptfoo`
  - oracle: `skill causing an action outside its stated purpose`
- `Direct tool functions`
  - action: enumerate arguments, then attempt to reach a state changing function with attacker controlled arguments
  - tools: `d20-agentdojo`
  - oracle: `state change from an induced call`

## Defense mirror

The other half of every row. An offensive entry with no matching detection and control is
incomplete, because the practical question is always against which defence.

| attack | detect | control | rule |
|---|---|---|---|
| tool poisoning | tool description changed or containing instructions | pin and review descriptions, treat as code | description hash change |
| indirect injection via tool output | tool output containing instructions followed by a call | label tool output as data | instruction pattern in tool output |
| excessive agency | call outside the task scope | per task scoping, confirmation for writes | call outside scope |
| skill supply chain | skill file added or modified | review, pin, sandbox | skill registry change |
| credential exposure to agent | agent reading secrets it does not need | no standing credentials, scoped tokens | secret access by agent |
