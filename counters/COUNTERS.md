# Counters by control class

Generated by `scripts/render-counters.py` from `data/counters/classes.json`. Do not edit by hand.

A defender reads this to find the gap in their own control. A researcher reads it the other way:
the blind spot column is the whole attack surface of that control, and the cost column is what
exploiting it will cost you.

The classes are the same ids the companion atlas uses, so a pattern's `counter` field and a
record here refer to the same thing.

## C01 object level authorisation

**Mechanism.** a per object ownership check on every read and write, evaluated after the object is fetched

**What it sees.** the caller and the record owner, when both are present at the same layer

**What it structurally cannot see.** paths that fetch the object without going through the checked function, such as a bulk export, a report, a relation traversal or an admin view

**The bypass.** reach the object through any route that does not call the checked function

**What that costs.** low: usually a parameter change on an alternate endpoint

**The rule that would catch it.** an access log where one principal touches objects whose owner column differs, correlated across endpoints

**Atoms.** A02 trust boundary crossing, A03 identity confusion

## C02 function level authorisation

**Mechanism.** a role or permission check per operation, deny by default, declared centrally

**What it sees.** the operation name and the caller's role set

**What it structurally cannot see.** operations that are composed at runtime, and the difference between a role that exists and a role that should reach this object

**The bypass.** find an operation not covered by the declaration, or one whose declaration is stale

**What that costs.** low to medium: needs route enumeration, rewarded by any undocumented endpoint

**The rule that would catch it.** a request to a route with no matching policy entry, which is a configuration alert rather than a traffic one

**Atoms.** A02 trust boundary crossing, A15 configuration divergence

## C03 binding allowlist

**Mechanism.** an explicit field allowlist per operation, never object hydration from request data

**What it sees.** the field names the request carries

**What it structurally cannot see.** nested and association writes, where the allowlist covers the parent and the child object is bound by a different rule

**The bypass.** write through a relation or a batch operation the allowlist does not model

**What that costs.** low if a relation exists, medium otherwise

**The rule that would catch it.** a write where a field changed that the endpoint's allowlist does not contain

**Atoms.** A05 type and shape confusion, A02 trust boundary crossing

## C04 identity canonicalisation

**Mechanism.** one normalisation form for every identifier, exact match, verified linking between providers

**What it sees.** the identifier as submitted and its canonical form

**What it structurally cannot see.** identifiers the canonicaliser does not know about, such as provider specific aliases, unicode confusables and case folding that differs per backend

**The bypass.** find two spellings that pass canonicalisation and collide at the store

**What that costs.** medium: requires probing the normaliser, not guessing it

**The rule that would catch it.** two accounts or sessions resolving from one credential, visible as a uniqueness violation after the fact

**Atoms.** A03 identity confusion

## C05 state machine integrity

**Mechanism.** invariants enforced per transition, with separation of duties where the process requires it

**What it sees.** the current state and the requested transition

**What it structurally cannot see.** the same invariant expressed in two places, such as an API and a batch job, and any transition performed by a migration

**The bypass.** act on the state directly through a second writer

**What that costs.** medium: needs a second surface that writes the same record

**The rule that would catch it.** a state value reached without the transition event that should precede it

**Atoms.** A04 state confusion, A10 logic assumption violation

## C06 credential and token policy

**Mechanism.** atomic single use for reset and invite tokens, subset scopes for delegation, verified identity for every claim

**What it sees.** the token's claims, signature, expiry and use count

**What it structurally cannot see.** the lifetime of the permission behind the token, and every token minted before a revocation

**The bypass.** use a token inside its validity window after the permission behind it changed

**What that costs.** low if a revocation window exists, high otherwise

**The rule that would catch it.** a token used after the subject's rights changed, correlated on subject rather than on token

**Atoms.** A03 identity confusion, A09 cryptographic weakness

## C07 parser strictness

**Mechanism.** one parser for the whole path, rejecting duplicates, alternates and ambiguous framing

**What it sees.** the bytes it parsed and anything it rejected

**What it structurally cannot see.** the other parser downstream, whose existence is the entire precondition for a desync

**The bypass.** find a second interpreter in the path and a message both accept differently

**What that costs.** medium: needs a byte level client and knowledge of the chain

**The rule that would catch it.** a request the edge logged differently from the origin, which requires comparing two logs rather than one

**Atoms.** A01 interpreter confusion, A15 configuration divergence

## C08 path and namespace control

**Mechanism.** canonicalise once, then verify containment against a fixed root, with no user controlled path component

**What it sees.** the canonical path and whether it sits under the root

**What it structurally cannot see.** symlinks and junctions created after the check, and any component the application resolves later

**The bypass.** create a link between check and use, or reach a resolver that reinterprets the name

**What that costs.** medium to high: needs a write primitive as well as a read

**The rule that would catch it.** a resolved path whose realpath differs from the checked path, which almost nobody logs

**Atoms.** A06 path and namespace confusion

## C09 cache and key discipline

**Mechanism.** every input that varies the response is part of the key, and authenticated responses never enter a shared cache

**What it sees.** the key it built and the response it stored

**What it structurally cannot see.** inputs it did not model, such as a header it forwards, a cookie it ignores and normalisation it applies after keying

**The bypass.** find an input that changes the response and is absent from the key

**What that costs.** low: usually one request to plant, one to read

**The rule that would catch it.** a cached response whose body contains a value from a different request's headers, found by diffing stored objects

**Atoms.** A04 state confusion, A06 path and namespace confusion

## C10 cost and resource control

**Mechanism.** per operation cost budgets and per principal quotas, enforced before the work is done

**What it sees.** the declared cost of an operation and the principal's spend so far

**What it structurally cannot see.** operations whose real cost differs from the declared one, which is every resolver that expands a relation

**The bypass.** find an operation that under declares its cost

**What that costs.** low: one request shape

**The rule that would catch it.** spend per operation diverging from the declared budget across a population of requests

**Atoms.** A07 resource exhaustion

## C11 audit integrity

**Mechanism.** structured append only logging with attribution, held where the audited identity cannot edit it

**What it sees.** the acts the application chose to log, and the principal the application believed

**What it structurally cannot see.** acts performed through a path that does not log, and any act where the principal was fabricated upstream

**The bypass.** act through an unlogged path, or make the log attribute the act to someone else

**What that costs.** low if an unlogged path exists

**The rule that would catch it.** a state change with no corresponding audit record, found by reconciling state against the log rather than reading the log

**Atoms.** A08 information exposure, A03 identity confusion

## C12 protocol lifecycle

**Mechanism.** retired versions decommissioned, one policy point rather than one per version

**What it sees.** the version in use and whether it is still permitted

**What it structurally cannot see.** the older version nobody decommissioned, and the policy point that only some routes pass through

**The bypass.** use a version or a route that skips the policy point

**What that costs.** low: usually a header

**The rule that would catch it.** traffic on a version whose retirement date has passed, which is a configuration report

**Atoms.** A15 configuration divergence, A01 interpreter confusion

## C13 maintenance and process

**Mechanism.** controls that live in process, infrastructure or review: patching cadence, dependency freshness, offboarding, review depth

**What it sees.** whether a step in the process happened, if anyone records it

**What it structurally cannot see.** the gap between the process and the work, and every exception granted under time pressure

**The bypass.** wait for the gap, or find the exception that was never revoked

**What that costs.** time rather than requests, which is why it is the cheapest class for a patient attacker

**The rule that would catch it.** a step that has no record, and a control whose exception register has no expiry

**Atoms.** A11 dependency compromise, A15 configuration divergence, A14 human manipulation

## C99 unclassified

**Mechanism.** no mechanism: the counter did not match any class, which is a classifier gap rather than a control

**What it sees.** nothing, because it is an absence

**What it structurally cannot see.** whatever the unmatched counters were describing

**The bypass.** not applicable; an unclassified counter means the taxonomy needs the case, not that a bypass exists

**What that costs.** unknown by construction

**The rule that would catch it.** the size of this class itself, which should stay small and does not always
